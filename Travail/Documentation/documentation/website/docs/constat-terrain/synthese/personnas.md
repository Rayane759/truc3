# Personas – Platform Engineering

Ce document présente une segmentation des utilisateurs de la plateforme basée non pas sur le niveau d’expérience, mais sur leur **relation à la plateforme**.

**Approche**: La segmentation repose sur un principe clé :

> Ce qui structure les besoins n’est pas la séniorité, mais la manière d’interagir avec la plateforme.

## 🟢 Persona 1 — Développeur “consommateur de plateforme”

### 🧾 Profil

* Regroupe juniors, intermédiaires et certains seniors
* Description : Ce sont des utilisateurs qui se concentre principalement sur le développement d'application. En dehors de ce périmètre ils sont peu à l'aise. Ils reposent sur des experts pour tout ce qui CI/CD, mise en place d'environnements, debuggages de leurs applications
* La plateforme est un moyen, pas un sujet. 

### 🎯 Objectifs

* Être autonome
* Aller vite
* Minimiser la charge cognitive

### 😤 Irritants

* Complexité inutile
* Multiplicité des outils
* Manque de self-service
* Documentation peu claire

### 💡 Besoins

* Parcours simples
* Templates prêts à l’emploi
* Self-service
* Feedback rapide

### 🧩 Attente clé

> “Je veux que ça marche sans réfléchir”

## 🟣 Persona 2 — Développeur “avancé / contributeur plateforme”

### 🧾 Profil

* Développeur expérimenté
* Interagit avec les couches techniques (CI/CD, infra, observabilité)
* Peut être référent technique

### 🎯 Objectifs

* Comprendre le fonctionnement
* Garder le contrôle
* Optimiser et débloquer
* Contribuer

### 😤 Irritants

* Outils opaques
* Manque de visibilité
* Automatisation insuffisante
* Processus lourds

### 💡 Besoins

* Observabilité fine
* APIs / CLI fiable, standardisé
* Possibilités d’override
* Automatisation avancée

### 🧩 Attente clé

> “Je veux comprendre et contrôler, pas subir”


## 🟠 Persona 3 — Manager / Lead technique

### 🧾 Profil

* Lead tech ou manager d’équipe
* Interface entre développeurs et production

### 🎯 Objectifs

* Assurer la delivery (est ce que les process de livraison répondent à mon besoin)
* Garantir la stabilité
* Piloter les équipes
* Connaitre et anticiper les changements
* Avoir une vue transverses

### 😤 Irritants

* Manque de visibilité
* Communication fragmentée
* Instabilité des outils
* Outil pas toujours aligné avec les besoins

### 💡 Besoins

* Dashboard global
* Vision des dépendances
* Communication centralisée
* Fiabilité de la plateforme

### 🧩 Attente clé

> “Je veux piloter sans être dans le détail technique”
